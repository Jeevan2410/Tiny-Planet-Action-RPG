# Assets

Everything you see and hear in this game is generated by the code in this
repository. There are no `.glb`, `.png`, `.mp3` or `.wav` files anywhere in
`public/`, and the production bundle pulls in no third-party media.

This document explains that choice, and — since the brief pointed at a specific
set of open-source libraries — exactly where to plug authored art in instead.

## Why procedural

| | Procedural | Imported |
| --- | --- | --- |
| Licences to track | none | one per model, per texture, per sound |
| First load | one JS bundle | bundle + megabytes of media |
| Draw calls per prop | 1 (baked vertex colours, shared material) | 1 per material |
| Variation | free (seeded RNG) | one mesh per variant |
| Fidelity ceiling | low-poly stylised | whatever you can author |

For a small toon-shaded action-RPG the trade lands on the procedural side: the art
direction wanted flat facets and hard colour bands, which is exactly what you get
from primitives with baked vertex colours, and the whole planet regenerates from a
single integer seed. The ceiling is real, though — if you want authored characters
with hand-keyed animation, swap them in as below.

`src/render/GeoBuilder.ts` is the workhorse: it accumulates transformed primitives
into one geometry with per-vertex colours, so a tree, a house or a whole village is
a single mesh with one shared material.

## Swapping in authored models

### Where models come from

| Library | Licence | Good for |
| --- | --- | --- |
| [Kenney](https://kenney.nl) | CC0 | Prop kits (Nature, Platformer), *Animated Characters* — a rigged humanoid with idle/walk/run |
| [Quaternius](https://quaternius.com) | CC0 | Stylised low-poly models, plus the Universal Animation Library (retargetable, fully CC0) |
| [Poly Haven](https://polyhaven.com) | CC0 | Higher-detail hero props, HDRIs |
| [ambientCG](https://ambientcg.com) | CC0 | PBR textures |
| [Mixamo](https://mixamo.com) | Free with an Adobe account, free for commercial use | A rigged humanoid plus a large animation library. Still online, but in maintenance mode — Quaternius' library is the fully-CC0 alternative |
| [Sketchfab](https://sketchfab.com) | **Varies per model** | Anything — but check the licence on each model before shipping it |

Drop `.glb` files in `public/models/` and they will be served as-is.

### Replacing a character

Character models are built by `src/entities/Models.ts`, which returns:

```ts
interface CharacterModel {
  root: Group;               // added to the actor's group
  rig: Rig;                  // named bones the pose functions drive
  material: MeshToonMaterial;// one instance per character, for hit flashes
  socket?: Object3D;         // weapon attach point in the right hand
  height: number;
}
```

To use a GLB instead, keep that shape:

```ts
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { toonUnique } from '../render/ToonMaterials';
import { Rig } from './Rig';

const loader = new GLTFLoader();

export async function buildHeroFromGlb(url: string): Promise<CharacterModel> {
  const gltf = await loader.loadAsync(url);
  const root = gltf.scene;

  // Force the toon look onto whatever the artist shipped.
  const material = toonUnique({ steps: 3 });
  root.traverse((child) => {
    const mesh = child as Mesh;
    if (!mesh.isMesh) return;
    const source = mesh.material as MeshStandardMaterial;
    const toon = material.clone();
    if (source.map) toon.map = source.map;
    else toon.color.copy(source.color);
    mesh.material = toon;
    mesh.castShadow = true;
  });

  // Map the artist's bone names onto the ones the pose functions expect.
  const find = (name: string) => root.getObjectByName(name)!;
  const rig = new Rig(root, {
    body: root,
    torso: find('mixamorigSpine'),
    head: find('mixamorigHead'),
    armL: find('mixamorigLeftArm'),
    elbowL: find('mixamorigLeftForeArm'),
    armR: find('mixamorigRightArm'),
    elbowR: find('mixamorigRightForeArm'),
    hipL: find('mixamorigLeftUpLeg'),
    kneeL: find('mixamorigLeftLeg'),
    hipR: find('mixamorigRightUpLeg'),
    kneeR: find('mixamorigRightLeg'),
  });

  return { root, rig, material, socket: find('mixamorigRightHand'), height: 1.8 };
}
```

Nothing else changes: `Player` and `Enemy` only ever touch `rig`, `material`,
`socket` and `height`.

### Using baked animation clips instead of the pose rig

The pose rig (`src/entities/Rig.ts`) exists because combat wanted frame-level
control over wind-up and recovery timing, which is awkward to tune in baked clips.
If you would rather use Mixamo/Quaternius clips, replace the `pose*` methods on
`Player`/`Enemy` with an `AnimationMixer`:

```ts
const mixer = new AnimationMixer(model.root);
const clips = Object.fromEntries(gltf.animations.map((c) => [c.name, mixer.clipAction(c)]));
// in update(): mixer.update(rawDt)
// on state change: clips[next].reset().fadeIn(0.12).play(); clips[prev].fadeOut(0.12);
```

Keep the telegraph timings in `ENEMY_CONFIG` as the source of truth and scale clip
playback to match — the readability of the wind-up matters more than the animation.

### Replacing props

`buildProp(kind, biome, rng)` in `src/world/Props.ts` returns a `BufferGeometry`
per biome palette; `scatterProps` builds one `InstancedMesh` per biome × kind from
it. To use GLB props, return the loaded geometry from `buildProp` instead. Two
things to keep:

- **Bake the biome tint into vertex colours** if you want one shared material.
  Otherwise give each kind its own material and accept the extra draw call.
- **Keep the bounding sphere**: `scatterProps` relies on
  `InstancedMesh.computeBoundingSphere()` for the per-biome frustum culling.

### Textures and skies

The sky is a shader gradient oriented by the player's local up
(`src/world/Sky.ts`). To use an HDRI from Poly Haven instead, load it with
`RGBELoader`, set `scene.environment`, and delete the dome — but note that a fixed
world-space environment map will not rotate with the player's up vector, so the
horizon will drift as you walk around the globe. The gradient exists for exactly
that reason.

## Audio

`src/audio/Audio.ts` synthesises every sound with the Web Audio API — 24 effects
plus an adaptive four-layer score. To use recorded audio instead:

| Source | Licence |
| --- | --- |
| [Kenney](https://kenney.nl/assets?q=audio) | CC0 — UI and interaction packs |
| [Freesound](https://freesound.org) | **Per upload**, mostly Creative Commons variants — check each file |
| [Sonniss GDC bundles](https://sonniss.com/gameaudiogdc) | Royalty-free, released annually |
| [Jamendo](https://jamendo.com) | CC music; **commercial use usually needs a paid sync licence per track** |

Swap the implementation of `AudioEngine.play(name, options)` for
[Howler.js](https://howlerjs.com) sprite playback and the rest of the game is
unaffected — every caller goes through that one method. The music scheduler is
separate (`scheduleMusic`/`playStep`) and can be replaced with a looping track per
biome plus a crossfade on `setIntensity`.

## Toon shading reference

The cel-shading approach here follows the
[three.js toon examples](https://threejs.org/examples/?q=toon) (MIT): a
`MeshToonMaterial` with a small `DataTexture` gradient map quantising diffuse
light into hard bands. Outlines are a separate inverted-hull pass —
`outlineMaterial` in `src/render/ToonMaterials.ts` — which inflates the geometry
along its normals and draws back faces only.
